## Distortion decision before implementation

The implementation uses additional LLZ squared error relative to decoded QSGD, divided by the original full-precision update's squared norm, summed over the whole client update. A zero-norm update requires zero extra error. This isolates the second stage; total error is logged separately. p=0 is always feasible. See the contract for deterministic ties, actual reply-byte costing and failure handling. The completed calibration froze budgets 5.9 and 7.0 before the full comparison.

Start with one p for each client update, as suggested by the notes. A per-tensor allocation rule is a later extension. Measure actual candidates rather than assuming the largest p gives the smallest packet. Account for extra selection/encoding time as well as bytes.
